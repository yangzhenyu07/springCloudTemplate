1. bind_tools 到底做了什么
==============================================================

  bind 之后: _ChatModelBinding

  调用后返回的其实是 AIMessage: AIMessage

2. tool_calls 里有什么
==============================================================
  本次返回 2 个调用：

    调用 1:
      name = weather       ← 工具名，用来查表
      args = {'city': '广州'}                  ← 模型填的参数
      id   = call_00_EFoDW501BIagg35y...  ← 回传结果时要对上这个
    调用 2:
      name = add           ← 工具名，用来查表
      args = {'a': 3, 'b': 4}                ← 模型填的参数
      id   = call_01_2S7MDSeCkD2vSIu4...  ← 回传结果时要对上这个

  【Java 对照】tool_calls 就是个 List<ToolCall>：
     record ToolCall(String name, Map<String,Object> args, String id) {}

  ⚠️ 三点要注意：
     ① args 是** dict**，但值是模型填的，可能不合法（要校验）
     ② id 必须原样带回，模型靠它把结果和调用对上
     ③ 一次可能返回**多个**（互不依赖时会并行）

3. 完整闭环，一步步手写
==============================================================
  ① 把问题发给模型：
     模型要求调用: [('weather', {'city': '广州'})]

  ② 我们执行工具：
     weather{'city': '广州'} → 广州：晴，26 摄氏度

  ③ 把结果包装成 ToolMessage 回传：
     ToolMessage(content='广州：晴，26 摄氏度', tool_call_id=call_00_ET_2xzkb84Zi...)

  ④ 模型基于结果作答：
     广州现在天气晴朗，气温 26 摄氏度。这个天气挺舒服的，适合外出，也不用带伞。

  >> 这四步是所有 Agent 框架内部在做的事。
     手写一遍，再看 LangGraph / create_agent 就全是透明的。

4. 多个工具要并发执行，别串行等
==============================================================
  模型一次返回 3 个调用：['weather', 'order_status', 'add']

  串行耗时: 0.001s
  并发耗时: 0.002s

  执行结果：
    weather        → 广州：晴，26 摄氏度
    order_status   → 订单 SO001：已发货，预计明天送达
    add            → 7

  >> 工具是 IO 密集型的（等网络），并发能显著提速。
     Java 视角：ThreadPoolExecutor + CompletableFuture.allOf
     ⚠️ 线程池大小要限制，别来 100 个调用就开 100 个线程。

5. tool_choice：强制控制是否调工具
==============================================================
  四个取值：
    'auto'   让模型自己决定（默认）
    'none'   不许调工具，只能直接回答
    'any'    必须调至少一个工具
    指定名字  必须调这一个工具

  ⚠️【DeepSeek 实测坑】开思考模式下，强制模式会 400：

    开思考 + auto → 成功，tool_calls=[]
    开思考 + any  → OpenAIInvalidRequestError
       错误信息含: 'Thinking mode does not support this tool_choice'

  ✅ 解法：强制模式用**关思考**的模型：

    关思考 + auto      → tool_calls=[]，正文='你好呀！很高兴见到你 😊\n\n随便说点的话'
    关思考 + none      → tool_calls=[]，正文='你好呀！很高兴见到你～😊\n\n既然你让我随'
    关思考 + any       → tool_calls=['weather', 'add']
    关思考 + weather   → tool_calls=['weather']

  >> 什么时候用强制模式：
     · 'none'    → 做纯聊天/摘要，不想让它调工具
     · 'any'     → 确定必须查外部数据才能答
     · 指定名字  → 做「信息抽取」：强制它把结果填进工具参数里
  ⚠️ DeepSeek 上用这几个，记得关思考。

6. 多轮：工具的结果决定下一步调什么
==============================================================
  用户: 查询订单 SO001 的状态，另外算一下 100 加 200

  第 1 轮：调用 ['order_status', 'add']
     → order_status: 订单 SO001：已发货，预计明天送达
     → add: 300

  第 2 轮：模型没再调工具，结束
  最终回答: 结果如下：

- **订单 SO001**：已发货，预计明天送达
- **100 + 200 = 300**

  >> 真实 Agent 就是这么循环：
     调工具 → 看结果 → 再决定调什么 → 直到不需要调为止
     ⚠️ 生产必须设**最大轮数**，否则模型可能无限循环烧钱。
