2. 多会话隔离：一个 session 一个文件
==============================================================

  [user_a] 的历史：
    [HumanMessage] 我叫yangzhenyu，我喜欢打篮球
    [AIMessage] 好的，记住你喜欢篮球

  [user_b] 的历史：
    [HumanMessage] 我叫taoyutian，我喜欢游泳
    [AIMessage] 好的，记住你喜欢游泳

  磁盘上的文件： ['muxiaoke.json', 'user_a.json', 'user_b.json']

>> 多会话隔离的本质：**给每个会话一个独立的 key**（这里是文件名）。
   换成 Redis 就是 key = chat:{session_id}；换成 MySQL 就是 where session_id = ?

==============================================================
3. 生产环境有哪些现成实现
==============================================================

  选型建议（按场景）：
   · 纯 LCEL 链、简单项目     → 自己实现（本文件这样）或 RedisChatMessageHistory
   · 用 agent                 → LangGraph checkpointer（见第 7 个文件，官方推荐）
   · 要跨会话的长期记忆        → LangGraph Store（langgraph.store）

  ⚠️ 生产必做的三件事（教学版没做）：
   ① 加锁 / 原子写：并发下「读-改-写」会丢消息
   ② 设过期：Redis 用 TTL，别让历史无限增长
   ③ 裁剪上限：历史太长要 trim（见第 4 个文件）
