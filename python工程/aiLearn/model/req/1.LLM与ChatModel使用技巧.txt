2. 返回值 AIMessage 里都有什么
==============================================================
type（角色）        : ai  <-- 固定是 'ai'
content（正文）     : 幂等性是指同一操作执行一次与执行多次所产生的结果或对系统状态的影响相同。
id                  : lc_run--01a1855e-2f0c-71a0-9dcd-0014f761f7d3-0  <-- 本次调用的唯一标识，用于追踪

response_metadata（服务端返回的元信息）:
   model_name      : deepseek-flash
   finish_reason   : stop

usage_metadata（token 消耗，计费依据）:
   input_tokens    : 37
   output_tokens   : 67
   total_tokens    : 104

>> 要点：
   · 不带解析器时拿到的是 AIMessage，要取文本用 .content
   · 加了 StrOutputParser 就直接拿到字符串，省掉 .content
   · usage_metadata 里 input/output tokens 是算钱和限流的依据

3. temperature 参数：稳定性的开关
==============================================================
temperature=0（偏稳定，适合抽取/分类/格式化输出）:
   第1次: 春天是万物复苏、草木萌发、风和日暖的时节。
   第2次: 春天是冰雪消融后，万物在一场温柔的风里重新睁开眼睛。

temperature=1（更有随机性，适合创意写作）:
   第1次: 春天是万物苏醒、风里带着花香与暖意的季节。
   第2次: 春天是万物苏醒、把世界重新染上嫩绿与花香的季节。

>> 经验值：0=确定性任务，0.3~0.7=日常对话，1+=创意生成
>> ⚠️ 实测提醒：temperature=0 也【不保证】逐字一致。
   刚才两次输出就不完全相同——模型服务端仍有采样不确定性。
   所以：需要严格稳定输出时，别只靠 temperature=0，
   要靠 JsonOutputParser / with_structured_output() 在格式层面兜底。

==============================================================
5. 输出解析器 StrOutputParser / JsonOutputParser
==============================================================
StrOutputParser —— 直接拿到 str:
  类型: TextAccessor | 内容: 开源高性能内存数据库

JsonOutputParser —— 自动解析成 dict:
  类型: dict | 内容: {'city': '杭州', 'weather': '晴'}
  取字段: 杭州 / 晴

>> 生产建议：关键场景用 JsonOutputParser + 重试，
   或者用 with_structured_output() 走模型原生的结构化输出能力。
